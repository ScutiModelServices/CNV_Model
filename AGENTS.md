# CNV_Model

Chat models served over HTTP through a JSON catalog and engine adapters, behind the shared model-service admin page, tokens and settings. Port 29204, env prefix `SERVICE_`, token prefix `cnv_`. Replaces `CNV_LFM3_Model`, `CNV_SparkX26_Model`, `CNV_MiniCPM52B_Model`, `CNV_BitNet2B_Model` (design: `AI/ModelServices/_docs/specs/2026-11-24-group-services-design.md`).

## Agent instructions
This file is the one instruction file for every coding agent; `CLAUDE.md` only imports it (`@AGENTS.md`). Edit this file, never `CLAUDE.md`.

## Commands (from this folder, venv `.venv`, managed by uv)
- Install: `uv sync` (`winget install astral-sh.uv` if uv is missing)
- Test: `uv run pytest -q`. `tests/test_admin_ui.py` needs Playwright and its browser and is skipped without it. On Windows, if uv fails with "cannot move the file to a different disk drive", set `UV_CACHE_DIR` to a folder on the same drive and `UV_LINK_MODE=copy`.
- Run: `run.bat run`, or `uv run python src/app.py` (add `--dotenv` to load `.env.local` and `.env`), or `docker compose --env-file .env.compose up -d --build`

## Rules
- Load downloaded weights only; no startup, warm-up or request downloads. Only the admin per-build Download downloads, then replica markers invalidate old weights. Missing files keep health/admin available and inference returns 503 with an admin Download hint.
- Models are catalog files, not code: `configs/models/<name>.json` (`src/catalog.py`). A build lists the engines that can run it; the catalog never picks one: the user does (saved `engines` setting per model, or `engine` per request, validated against the build's list). Engines are adapters in `src/adapters/` (`ollama`, `llamacpp`) behind `src/router.py`; a new engine is a new adapter plus an entry in `ENGINES`. A `llamacpp` model names its own sidecar in `url` (one `llama-server` holds one GGUF); there is no global llama.cpp URL. Keep injected fake adapters for tests (`tests/conftest.py`).
- Connection settings (`ollama_url`, `models_dir`, `ollama_parallel`) are admin settings saved in the shared `settings.json`; the env variables only seed the first start. They apply live within a second (`sync_forever` drops loaded models). There is no database in this service.
- `num_thread` is saved and reported only; Ollama chooses its threads. A 503 from an engine drops that loaded model; the next request loads it again.
- Follow the `model-service-parity` skill and `AI/ModelServices/_docs/SHARED-FEATURES.md` (what must match in every model service) and `AI/ModelServices/_docs/SERVICE-SPECIFIC.md` (what differs on purpose). A change to a shared feature goes to every service; a new difference goes into `SERVICE-SPECIFIC.md` in the same change.
- `web/index.html`, `src/tokens.py`, `src/settings.py`, `src/updates.py` and `.dockerignore` are copies shared with the other model services. Change one, copy it to the others, run `python tools/check_sync.py` in each repo.
- Builds: each catalog `builds` row is a quantization listed under its model; `src/builds.py` adds the memory estimate, the fit check (`src/hardware.py`) and live Hub sizes (cached in `hub-sizes.json` in the data volume; offline falls back to the stored size). The chosen build and engine per model are the saved `quants` and `engines` settings. There is no default model and no warm-up: every request names its `model`. Only `POST /admin/models/{name}/download` fetches weights.
- `POST /v1/chat` requires `model` (422 when missing, 404 when unknown) and takes an optional `engine` (422 when the build does not list it); `tools` need the model's `tools` capability (else 422); `schema`, request-level `thinking` and `project` are 422 (not carried over from MiniCPM and BitNet yet). Adapters get `tools=` only when a request has tools.
- The bitnet.cpp `llama-server` is old: it has no `--jinja` or chat templates, so `bitnet2b` sets `prompt: "bitnet"` and `src/adapters/llamacpp.py` renders the prompt and calls `/completion` (`render_bitnet`), as the old BitNet service did. A modern llama.cpp sidecar omits `prompt`.
- `cpu` (catalog, llamacpp): a required CPU flag, checked against `/proc/cpuinfo` (`builds.cpu_flags`) in the fit check, the download route and the load guard. bitnet2b needs `avx2`: on an AVX-only CPU the i2_s kernel produces `!!!!` garbage. Unreadable flags (Windows) allow the build.
- Lifecycle: `router.stopped` (saved `stopped` setting) refuses requests with 503 `ModelStopped`; stop calls the adapter's `unload` (Ollama `keep_alive: 0`). Marketplace additions are `marketplace.json` in the data volume (`catalog.with_extras`, Ollama builds only). `router.guard` (`fit_reason` in `src/app.py`) refuses to load a build that does not fit; it reads Hub sizes from the cache only, never the network.
- Downloads report to the shared `progress` module (`GET /admin/progress`; `SERVICE_WEIGHTS_MARKER` puts its file in the data volume so replicas agree) and run one at a time. Delete (shown as Uninstall) goes through the adapter's `delete`; the running build of a running model is refused. A loaded model (`router.state_of == "running"`) refuses run, download and delete with 409 until it is stopped (`loaded_guard` in `src/app.py`); other models are free.
- Port 29204 is the next free port in the CNV band; the four old CNV services keep 29200–29203 until their callers move (`docs/migration.md`).
- Behaviour changes update `README.md`, `deployment.md`, `docs/guide-web-ui.md`, `.env.example` and `CHANGELOG.md` in the same commit.
- Never read or print `.env`, `.env.local`, `.env.compose`, `tokens.json` or `settings.json`.
