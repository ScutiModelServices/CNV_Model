# Changelog

## 0.1.0

- Model states simplified: a model is **Off** or **On**, with one Turn on / Turn off button and a Preload button (Restart is gone from the page; the API keeps it, and gains `POST /admin/models/{name}/on`). The pill says whether the model is in memory, checked against Ollama (`/api/ps`) each time the page lists models, so it no longer shows "Loaded" after Ollama freed the model on its keep-alive. A model that is not really in memory no longer blocks Select, Download and Uninstall with "stop it first".
- Fix: a slow model load (minutes for a large model) held the router lock, which blocked Stop, the admin sync and other requests for the whole load. The lock is now held only to read and store the handle. The load balancer's read timeout is 330 s (was 130 s) so Preload no longer answers 504 while the load is still running.
- Fix: `inklingmini` answered with an empty string after one token. The Hub import carries generic stop tokens and no renderer. A catalog build can now name an Ollama `renderer` and `parser`; after Download pulls it, the service recreates the model from the same weights with them (no second download). All ten `inklingmini` builds use `inkling2`. Needs Ollama 0.40.18 or newer. A build pulled before this change needs one more Download, or the manual `ollama create`.
- No default build: `default_quant` is gone from the catalog files. A model has no selected build until an admin selects one, and only a downloaded build can be selected (`PUT /admin/models/{name}/run` answers 409 otherwise; the Select button is disabled with the reason). Requests for a model with nothing selected get 503 `has no selected build`. Existing installs must press Select once per model.
- New model `inklingmini` (Inkling 2 Mini, 26B MoE, from Thinking Machines) with ten Unsloth GGUF builds, `UD-IQ1_S` (7.4 GB) to `UD-Q8_K_XL` (21.8 GB), default `UD-Q4_K_M`, Ollama engine, capabilities `tools` and `thinking`. Text only (vision is not wired). The Ollama on the host must know the `inkling2` architecture. Sizes read from the Hub on 2026-11-25.
- Fix: a stopped model refuses requests even when the answer is cached (the cache was checked before the stop).
- Models table redesigned: one row per build and engine, the whole row opens the build details, the engine sits beside the memory estimate, and Select, Download and Uninstall are icon buttons that turn green and stay pressed when already true. A running download shows a progress bar with its percentage at the bottom of its row. Start, Stop and Restart show a spinner while they work. A loaded model cannot change build, download or uninstall (the service answers 409 "stop it first"); other models can. Delete is now called Uninstall.
- Model card: each build row has no table header; the name, note and Engine, Memory and Download chips stack on the left with the icon buttons on the right; Start, Stop and Restart form one segmented control; a build the CPU or memory cannot run shows its reason in a warning banner under the header; the build name is plain text with a Selected tag instead of an orange link.
- Fix: the sidebar collapse button did nothing on screens 1000 px wide or less (the rail was forced to 60 px). It now toggles between the icon rail and a 168 px sidebar there; narrow screens start as the rail.
- Whole admin page restyled like the Citadel admin apps: dark top bar (service, health, profile menu with the theme choice and Sign out), flat sidebar with the collapse button at its bottom (Ctrl+B), a page title with a one-line lede, panels and stat tiles on every page. Models and Marketplace get one panel per model with a builds table, state and build pills, helper popovers, a build-details drawer, a delete confirmation dialog and a download bar. `web/index.html` now differs from the copies in the other model services (`tools/check_sync.py` will report it).
- Models card redesigned: one card per model with a state chip (Stopped, Unloaded = takes requests but not in memory, Loaded = in memory) and per-build chips (Selected, Downloaded, Not downloaded, Runs on). The old "Running" button on a build meant only "selected".
- First release: one chat service for the models of `CNV_LFM3_Model`, `CNV_SparkX26_Model`, `CNV_MiniCPM52B_Model` and `CNV_BitNet2B_Model`, chosen by the `model` field.
- Catalog in `configs/models/*.json`; engines `ollama` and `llamacpp` (bitnet.cpp sidecar).
- Admin **Models** card: quantized builds under each model, live sizes from the Hub, per-build Use and Download.
- Ollama address, GGUF folder and parallel generations are live admin settings (env variables only seed the first start).
- `llamacpp` models carry their own sidecar `url` in the catalog; there is no `SERVICE_LLAMACPP_URL`.
- The bitnet.cpp sidecar exits (not restarted) on a CPU without AVX2.
- A build can require a CPU feature (`cpu` in the catalog): `bitnet2b` needs AVX2, so it is refused on CPUs without it instead of answering `!!!!`.
- Fix: the bitnet.cpp sidecar rejected `--jinja`; it now starts without chat-template flags and the service sends the BitNet prompt to `/completion` (catalog option `prompt: bitnet`).
- Download progress bar on the Models page (one download at a time) and a Delete button for downloaded builds.
- Start, Stop and Restart per model (stopped models refuse requests with 503); a Marketplace page that lists and adds other Hub quantizations of the supported models; builds that do not fit this machine cannot be downloaded, run, started or added.
- A build lists the engines that can run it and the user chooses: **Select** on the Models card, or `engine` in a request. Several models can stay loaded at once.
- No default model: every request names its `model`, so there is no default setting, no warm-up and no Updates card (per-build Download replaces it).
- Not carried over from the old services: JSON-schema output and project checkpoints (MiniCPM, BitNet), the transformers engine (BitNet).
